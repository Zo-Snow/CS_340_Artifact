# How do you write programs that are maintainable, readable, and adaptable? Especially consider your work on the CRUD Python module from Project One, which you used to connect the dashboard widgets to the database in Project Two. What were the advantages of working in this way? How else could you use this CRUD Python module in the future?

When writing code, it helps to break things down into smaller steps and maybe plan it out on paper first. That way, you get a clear picture of how everything fits together before jumping into the actual coding. Writing code in small chunks and testing it as you go, after making each little change, is a good way to make sure things are working as expected. For readability, short and simple comments in plain English really help anyone reading the code follow along easily. As for adaptability, it’s good to design the code in a way that’s flexible, using parameters that can be adjusted for different projects. This way, the same code can be reused in various contexts without needing to rewrite it from scratch. Just like with the CRUD Python module from Project One, we wrote it in a way that it can easily connect to different databases or dashboards, so one could apply that same code to future projects with minimal changes.
